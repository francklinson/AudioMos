# 音频切分对齐方案 — 完整框架总结

## 整体定位

音频切分对齐的功能是：**将一个长测试音频（~55s，含4段连续语音）自动切分为4个独立的短音频，每段与对应的参考音频（~12s，干净同内容）在内容和时间上精确对齐**，为后续带参考MOS分（PESQ、STOI等）计算提供对齐的输入。

---

## 流程总览

```

        │                          │
        ▼                          ▼
┌═══════════════════════════════════════════════════┐
║  阶段1: SNR估计                                   ║
║   - 前10帧估计噪声功率                             ║
║   - 整段总功率 - 噪声功率 → SNR(dB)                 ║
║   - 决定预增强策略(SNR<10dB时启用维纳滤波)           ║
╚═══════════════════════════════════════════════════╝
        │
        ▼
┌═══════════════════════════════════════════════════┐
║  阶段2: MFCC特征提取 + CMVN + Delta               ║
║   - 测试音频: 13阶MFCC → CMVN归一化               ║
║     → 13 delta → 13 delta-delta = 39维特征         ║
║   - 参考音频: 同上(不做预增强，参考本身干净)          ║
╚═══════════════════════════════════════════════════╝
        │
        ▼
┌═══════════════════════════════════════════════════┐
║  阶段3: 两级DTW全范围扫描 (核心定位)                ║
║                                                    ║
║  对每个参考音频:                                    ║
║                                                    ║
║  Level 1 — 粗扫描:                                  ║
║    步长 = 测试帧数/15 (~60帧/步)                    ║
║    全范围滑动DTW(余弦距离)                          ║
║    → 目标: 找到大致位置(精度~2s)                   ║
║                                                    ║
║  Level 2 — 精细扫描:                                ║
║    在粗扫结果±3s范围内                              ║

║    目标: 精确定位到帧级精度(~32ms)                 ║
║                                                    ║
║  置信度: 归一化DTW距离 < 0.5 → 0.9, < 1.0 → 0.7   ║
║          < 2.0 → 0.5, < 4.0 → 0.3, < 6.0 → 0.15   ║
╚═══════════════════════════════════════════════════╝
        │

┌═══════════════════════════════════════════════════┐

║                                                    ║

║                                                    ║
║  ① 按DTW offset切出12s测试段                       ║
║  ② 参考和测试段 → HPSS(k=51)提取谐波分量            ║
║     (时间轴中值滤波保留语音水平能量带               ║
║      抑制宽频非谐波噪声)                            ║
║  ③ 谐波域互相关 → 检测残留延迟lag                   ║
║  ④ 修正offset = DTW offset - lag                   ║
║  ⑤ 安全校验: quality<0.02或|lag|>2.0s则跳过          ║
║                                                    ║
║  精度提升: 残留lag从~370ms降至~0ms                   ║
╚═══════════════════════════════════════════════════╝
        │
        ▼
┌═══════════════════════════════════════════════════┐
║  阶段5: 等长切分                                    ║
║   - 从 修正后offset 到 offset + ref_dur(12s)       ║
║   - 精确到样本级(samples)                           ║
║   - 输出 _001.wav ~ _004.wav                       ║
║     (按ref_001~ref_004排序命名)                     ║

║   - PESQ/WB-PESQ(带参考)                           ║
║   - STOI(带参考)                                   ║
║   - DNSMOS(无参考, 用于对比)                        ║
║   - NISQA(无参考)                                  ║

```

## 模块职责

| 类/函数 | 职责 |

| `extract_harmonic_component()` | HPSS谐波提取(kernel_size=51) |
| `OptimizedMatcher._full_range_dtw_sweep()` | 两级DTW全范围扫描→帧级offset |
| `OptimizedMatcher._hpss_fine_align()` | HPSS谐波互相关→样本级精对齐修正 |
| `OptimizedMatcher.match_with_fallback()` | 单文件匹配(DTW→嵌入→低置信度) |
| `cut_all_audio_files_with_optimized_matcher()` | 批量切分主入口 |

| 函数 | 职责 |
|------|------|
| `get_ref_file_by_content()` | 匹配测试音频对应的参考文件(4级策略) |
| `compute_mos_scores_optimized()` | 并行计算多种MOS分 |

### `backend/app/api/mos.py` (API层)

接收上传→调用切分→调用MOS计算→返回结果

## 匹配策略优先级 (`get_ref_file_by_content`)

```
策略1: 文件名匹配
  (1) 完全一致 → (2) ref_前缀 → (3) ID匹配 → (4) 全名匹配
  耗时: <1ms

策略2: 指纹内容匹配 (Shazam)
  候选条件: conf ≥ 0.2 且 hash ≥ 10
  低SNR时指纹几乎全部失败(offset=0, conf≈0.05)
  耗时: ~1s

策略3: OptimizedMatcher（全范围DTW + 嵌入 + 回退）
  主方案: 全范围DTW(39维MFCC+CMVN+余弦距离)
  回退: SV模型嵌入向量匹配(TCF eres2net)
  耗时: ~2.3s/文件
```

## 架构决策记录

### 为什么不用Shazam指纹做主方案？

Shazam指纹基于频谱峰值检测+局部散列，在SNR<10dB时频谱峰值被噪声淹没，检测到的峰值主要是噪声峰值，hash匹配的偏移量收敛到0.00s（错误），置信度低至0.05。即使预增强处理后仍无改善。

### 为什么DTW+MFCC有效？

MFCC通过mel滤波器组压缩了高频细节，对加性噪声有一定鲁棒性。CMVN进一步减去了噪声的加性偏移。39维特征（13静态+13delta+13delta-delta）引入了时序动态信息。余弦距离对幅度变化不敏感。

### 为什么DTW精度不够需要HPSS？

DTW工作在帧级(hop=512, 32ms/帧)，精扫步长=3帧(96ms)。而噪声会导致MFCC特征产生系统性漂移，在10m降噪关文件上产生了~0.37s的偏移。HPSS谐波互相关在样本级(1/16000s)精度工作，将残留偏移修正到<0.01s。

### 为什么不用GCC-PHAT？

GCC-PHAT对所有频率同权，在低SNR下噪声频率占主导，相位信息被污染，导致对齐偏差>1s。仅在麦克风阵列的纯时延估计(N个通道相同信号)场景有效。

## 关键参数

| 参数 | 值 | 作用 |
|------|-----|------|
| 采样率 | 16kHz | 匹配处理统一采样率 |
| hop_length | 512 | STFT帧移(32ms/帧) |
| MFCC维度 | 13×3=39 | 静态+delta+delta-delta |
| DTW粗扫步长 | total_frames/15 | ~60帧(2s) |
| DTW精扫步长 | 3帧 | ~96ms |
| HPSS kernel_size | 51 | ~1.6s时间窗 |
| HPSS质量阈值 | 0.02 | 低于此值跳过修正 |
| 最大修正量 | ±2s | 超过认为DTW失效 |
