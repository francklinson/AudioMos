#### A1. restoration.py 末尾添加 WebSocket 端点
在 [backend/app/api/restoration.py](file:///home/zhouchenghao/PycharmProjects/AudioMos/backend/app/api/restoration.py) 末尾（`delete_task` 之后）添加，参照 [mos.py L1408-1440](file:///home/zhouchenghao/PycharmProjects/AudioMos/backend/app/api/mos.py#L1408-L1440) 模式：

```python
@router.websocket("/ws/{task_id}")
async def restoration_ws_endpoint(websocket: WebSocket, task_id: str):
    """音频修复任务实时进度推送"""
    await restoration_manager.connect(websocket, task_id)
    try:
        # 立即推送一次当前状态（前端连接后无需等待下一次更新）
        if task_id in restoration_tasks:
            t = restoration_tasks[task_id]
            await websocket.send_json({
                "status": t.get("status"),
                "progress": t.get("progress", 0),
                "message": t.get("message", ""),
                "step": _get_step_name(t.get("progress", 0)),
            })
        while True:
            # 心跳：每 2s 推送一次最新状态，确保前端断线重连后能同步
            if task_id in restoration_tasks:
                t = restoration_tasks[task_id]
                await websocket.send_json({
                    "status": t.get("status"),
                    "progress": t.get("progress", 0),
                    "message": t.get("message", ""),
                    "step": _get_step_name(t.get("progress", 0)),
                })
                # 任务终态 → 推送后断开
                if t.get("status") in ("completed", "failed"):
                    break
            await asyncio.sleep(2)
    except WebSocketDisconnect:
        pass
    except Exception:
        pass
    finally:
        restoration_manager.disconnect(task_id)
```

**关键设计**：连接时立即推送一次当前状态（解决"前端 WS 连接晚于后端首次推送"的时序问题）；终态时主动断开。

## 假设与决策

1. **不重做已落地代码**：算法层、restoration.py 已完成的 processor/进度/upload-batch/process 端点保持不变。
2. **WebSocket 而非轮询**：后端已具备 WS 推送能力（`update_restoration_progress` 已 `send_progress`），前端补 WS 客户端即可，与 MOS 一致。`restorationPollTimer` 死代码删除。
3. **WS 端点主动推送当前状态**：解决前端连接晚于后端首次推送的时序缺口（MOS 端点靠 `asyncio.sleep(1)` 轮询本地 dict，restoration 沿用但首连立即推一次）。
4. **终态主动断开 WS**：避免 completed/failed 后连接悬挂。
5. **波形单例 AudioContext**：浏览器限制约 6 个 AudioContext，单例复用避免泄漏。
6. **增量更新而非全量重渲染**：对齐 MOS，保证 WS 实时更新的 DOM 不被轮询覆盖。
7. **不改动 index.html 结构**：步骤进度容器由 JS 动态注入到任务卡片，无需改 HTML（upload-zone 拖拽直接绑事件）。
8. **`dereverberation_wiener` 已在后端注册**，前端算法列表自动从 `/algorithms` 接口拉取，无需前端硬编码。
9. **验证受限于环境**：若 sandbox 无 GPU/模型，则功能验证步骤改为"由用户在部署环境验证"，仅做静态检查。
